# ADR 0003: إصدار بروتوكول المزامنة ومعايير السلامة (Sync Protocol Versioning and Integrity)

# الحالة
مقبول (مُعدَّل بموجب RFC `2026-08-04-node-identity-trust`)

# السياق
بعد تحديد حدود حزمة المزامنة صراحة وتوفير حماية ضد إعادة الاستيراد (Replay Protection)، برز خطر جديد يتعلق بهشاشة البروتوكول:
*   التلف الصامت (ناتج عن مشاكل في وسائط التخزين).
*   التلاعب بالبيانات بعد فك التشفير أو أثناء النقل.
*   غموض سلوك التوافق مع تطور المخطط (Schema).

نحتاج إلى معيار أدنى للسلامة والإصدارات دون الدخول في تعقيدات التواقيع الرقمية الكاملة (PKI) في هذه المرحلة.

# القرار

1.  **طبقة التطبيق:** تظل دلالية فقط (Semantic)؛ لا تضاف إليها أي آليات للتجزئة (Hashing) أو التوقيع.
2.  **طبقة البنية التحتية:** إضافة مفاهيم السلامة تحت `infrastructure/sync/packages/integrity` باستخدام واجهة `PackageHasher`.
3.  **توسيع البيانات الوصفية:** إضافة حقل اختياري `integrity_hash: Option<String>` إلى `SyncPackageMetadata` لضمان التوافق مع الحزم القديمة.
4.  **تحديث مسار بناء الحزمة:** يتبع التسلسل: `تسلسل (Serialize) -> تجزئة (Hash) -> إرفاق البصمة -> تشفير (Encrypt)`.
5.  **التحقق عند الاستيراد:** يقوم المستورد بإعادة حساب البصمة ومقارنتها بالبصمة المرفقة، ويرفض الحزمة في حال عدم التطابق كخطأ في التحقق (Validation Error).
6.  **سياسة التوافق والإصدارات:**
    *   يظل `schema_version` هو المرجع النهائي للتوافق الدلالي.
    *   تصبح السلامة (Integrity) **إلزامية للحزم الجديدة**، مع السماح بقراءة الحزم القديمة لضمان استمرارية الهجرة.

# النتائج المترتبة
*   الحصول على بصمة حتمية للحزم وكشف التلاعب أو التلف.
*   إمكانية إضافة أنظمة التوقيع الرقمي لاحقاً فوق عقد التجزئة القياسي (Canonical-hash contract).
*   تحسين موثوقية الاستيراد دون إضافة أعباء تشغيلية متعلقة بسلاسل الثقة التشفيرية المعقدة حالياً.

# خارج النطاق
*   البنية التحتية للمفاتيح العامة (PKI/X.509) والشهادات الكاملة.
*   سياسات تدوير وإبطال المفاتيح (تُدار ضمن نموذج الهوية المعتمد في RFC `2026-08-04-node-identity-trust`).

# تعديل (Amendment — RFC `2026-08-04-node-identity-trust`)
*   رُفع بند "التواقيع غير المتماثلة (Asymmetric Signatures)" من خارج النطاق: تُسمح
    التواقيع غير المتماثلة بـ **Ed25519 فقط (RFC 8032)** وفق نموذج الهوية وسلسلة الثقة
    المعتمدين في `docs/architecture/rfcs/2026-08-04-node-identity-trust.md`.
*   يظل `schema_version` المرجع النهائي للتوافق الدلالي؛ توقيع الحزم الجديدة يكون
    إمّا integrity فقط (V1) أو Ed25519 عبر `signature_version = 2`.
*   البنية التحتية للمفاتيح العامة (PKI/X.509) والشهادات الكاملة **تبقى خارج النطاق**.
*   مرجع: RFC `2026-08-04-node-identity-trust.md` — الحالة: **مقبول (Accepted)**.
