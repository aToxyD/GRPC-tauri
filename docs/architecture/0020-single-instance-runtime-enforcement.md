# ADR 0020: فرض تشغيل نسخة واحدة من التطبيق (Single Instance Runtime Enforcement)

# الحالة
مقبول

# التاريخ
2026-05-16

# السياق
يتطلب النظام ضمانات صارمة لسلامة البيانات واتساق الوصول إلى قاعدة بيانات SQLite والـ WAL. تشغيل نسخ متعددة من التطبيق في نفس الوقت على نفس الجهاز قد يؤدي إلى تعارضات في الوصول إلى الملفات، أو ارتباك المستخدم بشأن حالة الجلسة، أو فشل في عمليات المزامنة والنسخ الاحتياطي التي تتطلب قفلاً حصرياً.

# القرار
اعتماد سياسة "النسخة الواحدة" (Single Instance) بشكل صارم على مستوى نظام التشغيل:

1.  **استخدام tauri-plugin-single-instance**: يتم دمج الإضافة الرسمية لـ Tauri لضمان وجود عملية (Process) واحدة فقط نشطة.
2.  **آلية الكشف**: عند محاولة تشغيل نسخة ثانية، تقوم العملية الجديدة بإرسال وسائط التشغيل (Arguments) إلى العملية الأصلية ثم تنتهي فوراً.
3.  **تجربة المستخدم**:
    *   تقوم النسخة الأصلية بتركيز النافذة (Focus) وإلغاء تصغيرها (Unminimize) لتنبيه المستخدم.
    *   يتم إظهار رسالة تنبيه واضحة باللغة العربية: "التطبيق يعمل بالفعل."
4.  **التسجيل (Logging)**: يتم تسجيل محاولات التشغيل المتعددة تحت الهدف `grpc::runtime` لأغراض التدقيق التشغيلي.

# النتائج المترتبة
*   **الإيجابيات**: منع تعارضات الوصول إلى الملفات، تحسين تجربة المستخدم عبر توجيهه للنافذة المفتوحة، وتبسيط إدارة حالة النظام.
*   **المقايضات**: يتطلب تشغيل التطبيق تهيئة مسبقة لآلية التواصل بين العمليات (IPC) التي توفرها الإضافة، مما قد يؤدي لتأخير طفيف جداً في التحقق أثناء بدء التشغيل.
*   **Fail-Closed**: في حال فشل تهيئة آلية التحقق من النسخة الواحدة، يجب أن يرفض التطبيق التشغيل لضمان عدم خرق السياسة الأمنية.
