# ADR 0009: المخطط الإصدار الثاني - التنسيق القياسي لسلامة الحزم والتواقيع

# الحالة
مقبول

# السياق
حدد ADR 0005 تجزئة السلامة (Hashing) على بايتات JSON بترتيب إصدار `serde_json`. هذا الترتيب مستقر لتخطيط واحد لـ serde ولكنه ليس عقداً محمولاً عبر التطبيقات المختلفة. يجب أن يستخدم توقيع الحزمة (HMAC) **نفس** تسلسل البايتات المستخدم في التجزئة.

# القرار

1.  تقديم **`schema_version = 2`** كإصدار التصدير الحالي (`SYNC_PACKAGE_SCHEMA_VERSION`).
2.  بالنسبة لـ `schema_version >= V2`؛ تكون مدخلات البصمة والتوقيع هي بايتات UTF-8 لـ **JSON القياسي (Canonical JSON)**:
    *   ترتيب مفاتيح الكائنات أبجدياً في كل مستويات التداخل.
    *   عدم وجود مسافات بيضاء غير ضرورية.
    *   تحتفظ المصفوفات بترتيب العناصر.
3.  بالنسبة لـ `schema_version == V1` (الإصدار القديم)؛ يتم الاحتفاظ بالسلوك السابق (لغرض الاستيراد فقط).
4.  يقبل المستوردون الإصدارات من **V1 إلى الإصدار الحالي** لضمان استمرارية استيراد الحزم القديمة حتى يتم إهمالها.

# النتائج المترتبة
*   يجب على المصدرين الانتقال إلى V2؛ حيث **تتغير** بايتات السلامة والتوقيع مقارنة بـ V1 لنفس المحتوى الدلالي — هذا تغيير متعمد في البروتوكول وليس انحرافاً صامتاً.
*   أي مشفر جديد يجب أن يطبق نفس القواعد القياسية أو يرفع إصدار المخطط وفقاً لـ ADR 0004.
