# ADR 0004: تغييرات البروتوكول تعتبر تغييرات جذرية (Protocol Changes are Breaking Changes)

# الحالة
مقبول

# السياق
أصبحت حدود المزامنة الآن واجهة بروتوكول تطبيقية ذات إصدارات محددة، وليست مجرد ملفات استيراد وتصدير عشوائية. في هذا المستوى من النضج، يتمثل الخطر الأكبر في انحراف البروتوكول بشكل غير مقصود:
*   تغيير بنية التسلسل (Serialization) دون مراجعة التوافق.
*   تغيير دلالات التجزئة (Hash) دون تحديث توقعات المستورد.
*   إضافة أو إزالة حقول البيانات الوصفية دون وجود سياسة هجرة.
*   تغيير قواعد المخطط (Schema) دون مصفوفة دعم صريحة.

هذه التغييرات يمكن أن تكسر التوافق بين العقد بصمت بعد فترة طويلة من الإصدار.

# القرار
يتم التعامل مع الأمور التالية كـ "تغييرات في العقد العام" (Public Contract Changes) افتراضياً:

1.  شكل الحزمة المتسلسلة، أسماء الحقول، الأنواع، وافتراضات الترتيب.
2.  دلالات مدخلات بصمة السلامة وقواعد القياس (Canonicalization).
3.  حقول `SyncPackageMetadata` والسلوك الإلزامي أو الاختياري لها.
4.  قواعد توافق الاستيراد (نافذة دعم `schema_version` وسياسة الرفض).

لكل تغيير من هذا القبيل، تعتبر الخطوات التالية إلزامية:
1.  **مراجعة التوافق**: أثر التغيير على المنتج والمستهلك ومسار الهجرة.
2.  **تحديث عقد اللقطة (Snapshot Contract)**: تحديث نماذج الحزم القياسية حيثما ينطبق.
3.  **اختبارات سلوك الاستيراد**: اختبار حالات النجاح والرفض الصريح.
4.  **تحديث ADR**: تحديث أو إنشاء سجل قرار معماري جديد إذا تغير السلوك دلالياً.

# النتائج المترتبة
*   تصبح استقرار البروتوكول قابلة للفرض من خلال الإجراءات، وليس فقط من خلال أسلوب الكود.
*   يتم اكتشاف الكسور أثناء التطوير عبر اختبارات العقد وقوائم مراجعة التدقيق.
*   تصبح ترقيات العقد المتعددة في المستقبل أكثر أماناً وقابلية للتوقع.
