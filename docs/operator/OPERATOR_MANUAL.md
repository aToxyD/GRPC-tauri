# دليل المشغل (Operator Manual)

# الهدف
يهدف هذا الدليل إلى توفير إرشادات تشغيلية شاملة لمشغلي نظام GRPC (Gestion des Restaurants de la Protection Civile)، لضمان تنفيذ العمليات اليومية والمالية بدقة وأمان، والحفاظ على سلامة (Integrity) البيانات.

# النطاق
يغطي هذا الدليل العمليات التشغيلية لكل من مستوى "الولاية" (Wilaya) ومستوى "الوحدة" (Unit)، بما في ذلك إدارة الجلسات، العمليات اليومية، الانتقال المالي، والنسخ الاحتياطي.

# المتطلبات
*   صلاحيات وصول مفعلة (اسم مستخدم وكلمة مرور).
*   فهم أساسي لدور الجهة (ولاية أو وحدة).
*   الالتزام بسياسات الأمان والحفاظ على سرية المفاتيح.

# المبادئ التشغيلية للنظام
يعتمد نظام GRPC على مبادئ هندسية صارمة:
*   **Offline-first**: العمل بكفاءة دون الحاجة لاتصال دائم بالإنترنت.
*   **Deterministic**: ضمان نتائج متوقعة وثابتة لنفس العمليات.
*   **Fail-Closed**: إيقاف العمليات فوراً عند اكتشاف أي خلل في السلامة (Integrity) لحماية البيانات من التلف (Corruption).

# الفروق التشغيلية بين الأدوار
*   **الولاية (Wilaya):** تملك السلطة الإدارية لتعريف المنتجات، مراقبة الوحدات التابعة، وإصدار "حزمة إغلاق السنة المالية" (Fiscal Closure Package).
*   **الوحدة (Unit):** مختصة بالعمليات الميدانية (مخزون، استهلاك، طلبات) وتنفيذ أوامر الإغلاق المالي المستلمة من الولاية.

# خطوات التنفيذ

## 1. إدارة الجلسات (Session Management)
*   **الدخول:** يتم عبر واجهة تسجيل الدخول المؤمنة. يستخدم النظام خوارزمية Argon2 لتأمين كلمات المرور.
*   **مهلة الجلسة (Session Timeout):** يتم تسجيل الخروج تلقائياً عند الخمول. يظهر تنبيه قبل 5 دقائق من انتهاء الصلاحية.
*   **الخروج الآمن:** يجب دائماً استخدام خيار تسجيل الخروج عند مغادرة المحطة لضمان إنهاء الـ Transaction Boundary الحالي.

## 2. العمليات اليومية (Daily Operations)
*   **إدارة المخزون:** تسجيل الوارد والصادر بدقة لضمان مطابقة الـ Snapshot الفعلي مع السجلات.
*   **المزامنة (Sync):** يتم تبادل البيانات بين الوحدات والولاية عبر "حزم مزامنة" (Sync Packages) مشفرة وموقعة رقمياً.

## 3. العمليات المالية (Fiscal Operations)
*   **سلطة الإغلاق:** تقوم الولاية بإنشاء "حزمة انتقال السنة المالية" (Fiscal Transition Package).
*   **التطبيق (Application):** تقوم الوحدة باستيراد الحزمة وتطبيقها.
*   **التحقق الصارم:** يتطلب النظام إدخال عبارات تأكيد نصية (Typed Confirmation) مثل `APPLY-FISCAL-TRANSITION` لتنفيذ العمليات الحساسة.

## 4. النسخ الاحتياطي والاستعادة (Backup & Restore)
*   **النسخ الاحتياطي (Backup):** يتم يدوياً عبر واجهة الإدارة. يستخدم النظام SQLite Backup API لضمان اتساق البيانات.
*   **الاستعادة (Restore):** تخضع لسياسة Replay Protection، حيث يُمنع استعادة نسخة أقدم من آخر "نقطة تفتيش" (Checkpoint) معتمدة لمنع التلاعب بالسجلات التاريخية.

# حالات الفشل وإجراءات الاسترجاع (Recovery)
*   **تنبيه (WARNING):** خلل غير حرج يسمح باستمرار العمل مع ضرورة المتابعة.
*   **تلف (CORRUPTED):** فشل في اختبار السلامة (Integrity Check) يؤدي لإيقاف العمليات الحساسة.
*   **حرج (CRITICAL):** تلف بنيوي يتطلب تدخل المسؤول واستعادة (Restore) من نسخة احتياطية نظيفة.

# ملاحظات السلامة
*   **يُمنع منعاً باتاً** تعديل ملفات قاعدة البيانات (SQLite) يدوياً.
*   لا يجوز تجاهل رسائل التحذير المتعلقة بـ Audit Chain أو Integrity.

# السجلات والتدقيق (Audit & Logging)
يتم تسجيل كافة العمليات الحساسة في "سجل التدقيق" (Audit Log) بشكل غير قابل للتعديل. يمكن للمشغل تصدير هذه السجلات للمراجعة الدورية.
