# Runbook: فقدان المفاتيح وإعادة التزويد (Key Loss & Re-Provisioning)

# الهدف
توثيق السلوك عند فقدان أو تلف المفاتيح، والمسار الصحيح لإعادة تزويد العقدة، وفق ما أُثبت
عبر إشهاد A2 (2026-08-09) وقرارات ADR-0041/0042.

# النطاق
- مفتاح التطبيق (`appkey.age` / كلمة المرور).
- مفتاح توقيع الحزم `GRPC_PACKAGE_SIGNING_KEY`.
- مفتاح جذر السلطة `GRPC_ROOT_PUBLIC_KEY`.
- **مفتاح العقدة (هوية العقدة)** وأثره على التراخيص.
- فقدان/تلف الـartifact والمرساة.

# مراجع

- `docs/architecture/0042-licensing-consumer-integration.md` — ربط الترخيص بالعقدة.

# 1. مفتاح التطبيق (App Key)

## فقدان كلمة المرور
| الحالة | النتيجة (مثبتة ADR-0041 §8) |
|---|---|
| فقدان كلمة مرور `appkey.age` **مع** النسخة الاحتياطية | **فقدان البيانات المشفرة** — التعمية مشفّرة بمفتاح لا يمكن الوصول إليه (Fail-Closed) |
| نسخة احتياطية مأخوذة عند التهيئة | يمكن الاستعادة عبر المسار البيئي `GRPC_APP_KEY` (هوية `age` صالحة) أو إعادة التزويد |

الإجراء:
1. استخدم النسخة الاحتياطية المصدرة (عند التهيئة، اختيارياً): `export_app_key_backup` يوفّر
   مسار إعادة تصدير محروساً (يتطلب حالة مفتوحة).
2. بديلاً: اضبط `GRPC_APP_KEY` في بيئة النظام (Override) — يُحترم فوق المخزن في حل المفتاح.

> **أسطول WILAYA ↔ UNIT (ADR-0041 §10)**: لإعادة التزويد/الهجرة يُستخدم **نفس مسار
> `GRPC_APP_KEY`** بقيمة واحدة متطابقة بين العقد (المفتاح المشترك مطلوب لفك حزم
> التبادل المشفّرة بمفتاح المُصدِّر). **يُحظر نسخ `appkey.age` بين العقد** — المخزن
> محلي محمي بكلمة مرور وليس وسيلة تبادل؛ التبادل عبر متغير البيئة فقط.

## فساد/فقدان `appkey.age`
- ملف تالف/غير قابل للتحليل → يبقى مقفلاً ويعامل كإجراء مطلوب من المشغّل (لا تراجع لمسار آخر).
- كلمة مرور خاطئة → `UnlockFailed` — يبقى مقفلاً.
- إذا أُلغي قفل المخزن بمفتاح **مختلف** عن الذي شفّر بيانات العقدة → فشل فك تشفير المادة
  المشفّرة (يُكتشف عبر بيانات العقدة غير القابلة للفك، وليس عبر تبديل صامت).

# 2. مفتاح توقيع الحزم `GRPC_PACKAGE_SIGNING_KEY`
- مفتاح أسطول مشترك بين كافة العقد؛ في حال تسربه: **دورانه فوراً في كل العقد** لمنع تلاعب
  بالحزم. (لا يتعلق بالترخيص؛ متطلباته في `security-production-keys.md`.)

# 3. مفتاح جذر السلطة `GRPC_ROOT_PUBLIC_KEY`
- يُستخدم للتحقق من شهادة إقلاع الهوية دون اتصال (عند `finalize`).
- ترتيب الحل: `GRPC_ROOT_PUBLIC_KEY` (بيئة) → المفتاح المضمّن `PROD_ROOT_PUBLIC_KEY`
  (placeholder في Release الحالي — راجع `trial-deployment-checklist.md`).
- **Fail-Closed (Release)**: طالما المضمّن هو متجه اختبار RFC 8032 §7.1 TEST 2،
  **يرفض النظام في Release** حلّه كـfallback — إقلاع WILAYA يتطلب `GRPC_ROOT_PUBLIC_KEY`
  بمفتاح عام حقيقي (غير TEST) حتى يُستبدل المضمّن بقرار رسمي.
- تدوير مفتاح Root = تحديث قيمة البيئة على كل عقدة (أو استبدال المضمّن في كود الإصدار).
  مستقل عن تدوير anchor الترخيص.

# 4. مفتاح العقدة (هوية العقدة) — الحرجة للترخيص
> **مفتاح العقدة هو مرجع ربط الترخيص** (`subject.id` = base64url لمفتاح العقدة العام).
> فقدان مفتاح العقدة أو إعادة تزويد الهوية يغيّر المفتاح → التراخيص القائمة تصبح
> `not-for-this-node` على الفور.

السيناريو:
1. فقدان/تلف سر مفتاح العقدة (مخزن `NodeKeyStore`) → لا يمكن فك تشفير المفتاح → Fail-Closed.
2. إعادة إقلاع الهوية دون اتصال: `begin_wilaya_provision` (زوج مفاتيح جديد + CSR) →
   توقيع السلطة → `finalize_wilaya_provision` → `issue_first_admin_key`.
3. مفتاح العقدة الجديد له `subject.id` جديد.
4. **إعادة سك ترخيص جديد من سلطة التراخيص** لمفتاح العقدة الجديد، ثم:
   `import_license` → `get_licensing_status` (نشط) → `verify_license` (`enforceable ≥ 1`).

> لا يُصلح ترخيص قديم على عقدة بمفتاح جديد؛ الحل الوحيد هو ترخيص جديد مرتبط بالمفتاح الجديد.

## مفتاح عقدة UNIT بالمسار المضمّن (Packaged-Identity — 2026-08-15، ADR-0044 §8.3)

- في `.unit` المضمّنة، مفتاح UNIT يُولَّد **في الذاكرة على WILAYA** عند التصدير ويُضمَّن
  مشفّرًا داخل الحزمة (لا يُخزَّن أبدًا في `NodeKeyStore` الخاص بـ WILAYA). عند الاستيراد
  يُثبَّت على `NodeKeyStore` الخاص بـ UNIT داخل معاملة التدقيق.
- **نموذج الانهيار**: إذا انقطعت العملية بعد كتابة المفتاح وقبل تركيب الهوية (مفتاح حاضر +
  هوية غائبة) → **أعد استيراد نفس `.unit`** — التثبيت يكتمل (الكتابة مطابقة = no-op).
- **إعادة التصدير = رفض**: بمجرد وجود هوية UNIT ACTIVE على WILAYA، لا يمكن تصدير `.unit`
  جديدة لنفس الوحدة (حارس ACTIVE المكرّر).
- **فقدان/فساد مفتاح UNIT بعد نجاح الإقلاع**: هذا المسار لا يضيف آلية استرداد — الاسترداد
  عبر مسار الدوران الحالي (B7 rotation: إعادة إصدار لاعتماد جديد) أو إعادة تزويد كوحدة
  جديدة بمُعرّف جديد (rollback = re-provisioning).

# 5. فقدان/تلف الـartifact أو المرساة

## فقدان/تلف الترخيص (الـartifact)
- الترخيص عرض مشتق مخزّن في قاعدة البيانات و**يبقى عبر إعادة التشغيل** (مثبت من A2).
- في حال فقدانه/تلفه: أعد استيراده من سلطة التراخيص (`import_license`) — إعادة استيراد نفس
  الـartifact عملية Idempotent (نفس `artifact_id`) وتستبدل العرض المشتق.
- للتحقق من سلامة التخزين: `verify_license` (يعيد فحص كل ترخيص مخزّن دون إعادة استيراد).

## فقدان المرساة (Trust Anchor)
- أعد تثبيت حزمة `provisioning-v1` عبر `import_trust_anchor` (يُثبَّت anchor نشط وحيد).
- بدون anchor، أي artifact معروض يُرفض (Fail-Closed).

# 6. ملخص الحالات (Fail-Closed)
| السيناريو | النتيجة |
|---|---|
| فقدان كلمة مرور appkey + النسخة الاحتياطية | فقدان البيانات المشفرة |
| مخزن تالف / كلمة مرور خاطئة | مقفل، لا تراجع لمسار آخر |
| تسريب `GRPC_PACKAGE_SIGNING_KEY` | تدوير فوري لكافة العقد |
| فقدان مفتاح العقدة | إعادة تزويد الهوية + **إعادة سك الترخيص** |
| فقدان الـartifact | إعادة استيراد idempotent من السلطة |
| فقدان المرساة | إعادة تثبيت الحزمة |
