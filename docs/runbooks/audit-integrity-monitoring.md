# Runbook: مراقبة سلامة التدقيق (Audit Integrity Monitoring)

# الهدف
توفير إرشادات لمسؤولي الولاية لمراقبة سلامة سجل التدقيق وضمان كشف أي محاولات تلاعب بالبيانات بشكل استباقي.

# النطاق
يطبق هذا الإجراء من قبل مسؤولي النظام (Wilaya Admins) عبر واجهة الإدارة.

# الخلفية التقنية
يستخدم سجل التدقيق سلسلة Hash تعتمد على SHA-256 لضمان عدم إمكانية التلاعب بالسجلات (Tamper-evidence). كل إدخال يحفظ بصمة الإدخال السابق، مما يجعل أي تعديل مكتشفاً فوراً.

# خطوات التنفيذ

## 1. الوصول إلى لوحة المراقبة
انتقل إلى: **الإدارة ← سلامة التدقيق (Audit Integrity)**

## 2. فهم حالة السلسلة (Chain Status)
| الحالة | المعنى | الإجراء المطلوب |
| :--- | :--- | :--- |
| ✅ **VALID** | كافة البصمات متطابقة وسلسة. | لا يوجد إجراء مطلوب. |
| 🚨 **BROKEN** | تم اكتشاف عدم تطابق في البصمات. | اتبع إجراءات الاستجابة للحوادث أدناه. |

## 3. المؤشرات الحيوية (Key Metrics)
*   **إجمالي السجلات**: العدد الكلي لسجلات التدقيق في قاعدة البيانات.
*   **سجلات مُتحققة**: عدد السجلات التي تمتلك `entry_hash` صالح.
*   **آخر Hash**: بصمة SHA-256 لأحدث سجل في السلسلة.
*   **آخر إدخال**: الطابع الزمني لأحدث عملية مسجلة.

## 4. أنواع الشذوذ (Anomaly Types)
| نوع الشذوذ | الخطورة | الاستجابة |
| :--- | :--- | :--- |
| `CHAIN_INTEGRITY_VIOLATION` | **CRITICAL** (حرجة) | استجابة فورية للحوادث. |
| `STALE_BACKUP` | **WARNING** (تحذير) | إنشاء نسخة احتياطية (Backup) جديدة فوراً. |
| `NO_BACKUP_RECORDED` | **WARNING** (تحذير) | التحقق من إعدادات النسخ الاحتياطي. |

# إجراءات الاستجابة للحوادث (في حال كسر السلسلة)
1.  **لا تقم بتعديل أي بيانات**: حافظ على الوضع الحالي كدليل تقني.
2.  سجل معرف أول سجل مكسور (`firstBrokenEntryId`) الظاهر على الشاشة.
3.  تحقق من عمود `entry_hash` في قاعدة البيانات للسجل المكسور باستخدام أدوات الإدارة.
4.  راجع من كان يملك صلاحية الوصول لقاعدة البيانات بين آخر سجل سليم وأول سجل مكسور.
5.  راجع سجلات أحداث نظام التشغيل (Windows Event Log) للبحث عن وصول مباشر للملفات.
6.  أبلغ مالك النظام؛ قد يكون مسار التدقيق قد تعرض للتلاعب.

# جدول المراقبة الدوري
| التكرار | الفحص |
| :--- | :--- |
| **يومياً** | التحقق من أن حالة السلسلة هي **VALID**. |
| **أسبوعياً** | مراجعة أي شذوذ (Anomalies) مسجل في القائمة. |
| **شهرياً** | التأكد من أن تاريخ آخر نسخة احتياطية لا يتجاوز 7 أيام. |

# الأوامر المتاحة
*   `get_audit_chain_status`: للتحقق السريع من حالة السلسلة.
*   `get_audit_health`: للحصول على تقرير كامل عن حالة السلامة والشذوذ.
