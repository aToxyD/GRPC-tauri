# Runbook: التحقق من سلسلة التدقيق (Audit Chain Verification)

# الهدف
يهدف هذا الدليل إلى توضيح كيفية التحقق من سلامة سجل التدقيق (Audit Log) والكشف عن أي محاولات تلاعب بالبيانات التاريخية.

# النطاق
يغطي هذا الإجراء العمليات اليدوية والآلية للتحقق من سلسلة الـ Hash في جدول التدقيق.

# الخلفية التقنية
يستخدم النظام سلسلة Hash متصلة في جدول `audit_log`؛ حيث يحتوي كل سجل على بصمة `entry_hash` وبصمة السجل السابق `previous_hash` (بنمط Blockchain بسيط)، مما يجعل أي حذف أو تعديل للسجلات القديمة يكسر السلسلة.

# خطوات التنفيذ

## 1. التحقق الآلي
يمكن استدعاء خدمة التحقق الداخلية (في حال توفرها عبر واجهة الإدارة أو سطر الأوامر):
```rust
AuditService::verify_audit_hash_chain()
```

## 2. التدقيق اليدوي (Spot Check)
1. اختر السجل رقم $N$.
2. أعد حساب SHA-256 لحقول السجل رقم $N-1$ (الإجراء، المستخدم، الطابع الزمني، معرف المورد، البصمة السابقة).
3. تأكد من مطابقة النتيجة لـ `previous_hash` في السجل رقم $N$.

# التعامل مع خروقات السلامة (Breaches)
في حال اكتشاف عدم تطابق:
*   **الأعراض**: ظهور خطأ "Audit Integrity Breach".
*   **الإجراء**: قفل قاعدة البيانات فوراً ومنع أي عمليات جديدة. التحقق من جدول `audit_log` للبحث عن صفوف محذوفة أو معدلة.
*   **الاسترجاع**: استعادة النظام من آخر **نسخة احتياطية موثوقة** (Trusted Backup) تم التحقق من سلامتها.

# ملاحظات السلامة
هذه الآلية لا تمنع التلاعب المادي بقاعدة البيانات ولكنها تجعله **ظاهراً وقابلاً للاكتشاف** عند أول فحص للسلامة.
