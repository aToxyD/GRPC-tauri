# دليل حوكمة مستودع GitHub (GitHub Repository Governance Guide)

يوثق هذا الدليل السياسات الصارمة الحاكمة لإدارة المستودع، وحماية الفروع، وتنسيق تدفق دمج التعليمات البرمجية وعمليات الإصدار في منصة GitHub لضمان نزاهة وجودة النظام.

> منذ A4.4، تخلّى المشروع عن GitLab واعتمد GitHub منصة استضافة و CI الوحيدة. كان الملف باسم `GITLAB_GOVERNANCE.md`؛ حُفظ التاريخ عبر `git mv`. راجع `ci_governance_audit.md` للسياق.

---

## 1. سياسة حماية الفروع (Protected Branches Policy)

* **الفروع المحمية (Protected Branches):**
  * يُعتبر الفرع الرئيسي `main` فرعاً محمياً بشكل دائم.
  * يُحظر تماماً الدفع المباشر (`git push`) للفرع `main`.
  * تُحمى فروع الإصدارات الرسمية (مثل `release/v*`) لمنع التعديل غير المعتمد بعد إتمام البناء.

* **قواعد دمج طلبات السحب (Pull Request Rules):**
  * يجب فتح طلب سحب (Pull Request - PR) لكل تعديل برمجي أو وثائقي.
  * يُحظر الدمج ما لم ينجح خط أنابيب التطوير والتحقق (CI) بالكامل بنسبة 100% (راجع `CI_CD_GOVERNANCE.md`).
  * يفرض النظام مراجعة واعتماد طلب السحب من قِبل **مراجعين (Reviewers)** قبل الدمج.

---

## 2. سياسة الدمج والتوقيع (Squash & Signed Commits)

* **سياسة الدمج الموحد (Squash Merge Policy):**
  * يجب تفعيل خيار `Squash commits` عند دمج أي طلب سحب للحفاظ على نظافة واتساق سجل التغييرات التاريخي للفرع الرئيسي وتسهيل عمليات التدقيق والتراجع.
* **التوقيع الرقمي للمساهمات (Signed Commits):**
  * يوصى بشدة بتفعيل توقيع الالتزامات رقمياً باستخدام مفاتيح GPG للتحقق من هوية المبرمجين ومنع هجمات انتحال الهوية البرمجية.

---

## 3. استراتيجية إدارة الإصدارات والترقيم (Release Tagging Strategy)

* يتم إصدار النسخ الرسمية للنظام حصراً عبر استخدام وسوم Git (Tags) الموقعة تشفيرياً، ويُدار التجميع والنشر عبر `release.yml` (`.github/workflows/release.yml`) الذي يُستدعى يدوياً بوسم محدد.
* يتبع الترقيم معيار الترقيم الدلالي (Semantic Versioning 2.0.0) بصيغة `vMajor.Minor.Patch`.
* CI العام (`.github/workflows/ci.yml`) يعمل تلقائياً على كل الفروع وطلبات السحب؛ أما e2e فيُشغَّل على الفرع الرئيسي وطلبات السحب المستهدفة له فقط.

---

## 4. مسار معالجة الطوارئ والتراجع (Hotfix & Rollback Processes)

* **إجراء الترقيع العاجل (Hotfix Process):**
  1. يتم إنشاء فرع ترقيع عاجل من نقطة الوسم الأخير للإصدار الفعال باسم `hotfix/vX.Y.Z`.
  2. يُمنع إجراء أي تغييرات بخلاف الإصلاح البرمجي الفعلي للخلل الحرج.
  3. يدمج فرع الترقيع العاجل في فرع `main` وفروع الإصدارات النشطة بعد مرور كامل الفحوصات الأمنية المعمارية تلقائياً.

* **سياسة التراجع الآمن (Rollback Policy):**
  * عند رصد خلل فادح أو تلف في البيانات بعد نشر إصدار جديد، يتم تفعيل التراجع الفوري للنظام عبر إعادة تحميل آخر نسخة احتياطية آمنة معتمدة، وتوجيه المشغلين لتنزيل حزمة الإصدار السابق الأكثر استقراراً.

* **خطة الطوارئ والاستعادة الذاتية (Emergency Recovery Process):**
  * في حال تعطل ملف قاعدة البيانات الفعالة على جهاز المشغل، يتم إطلاق تدفق الاستعادة الذاتية الآمنة الموثق في [TECHNICAL_DOCUMENTATION.md](file:///docs/technical/TECHNICAL_DOCUMENTATION.md) حيث يقوم النظام بفحص نزاهة النسخ الاحتياطية وإعادة البناء الذري التام لقاعدة البيانات في بيئة مؤقتة معزولة قبل اعتمادها كملف نشط فعال.
