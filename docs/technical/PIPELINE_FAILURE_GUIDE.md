# دليل معالجة فشل خطوط الأنابيب (Pipeline Failure Guide)

يوفر هذا الدليل إرشادات تفصيلية وهندسية للمطورين والمسؤولين لمعالجة وإصلاح حالات الفشل التي قد تطرأ على خطوط أنابيب الدمج المستمر (CI/CD Pipeline) في GitHub Actions (`.github/workflows/ci.yml`) بطريقة آمنة وموافقة للثوابت المعمارية للمشروع.

---

## 1. الفشل في تدقيق الأمان والسرية (Secrets Scanning Failures)

* **الأعراض:** فشل مرحلة `validate` مع ظهور رسالة:
  `❌ خطأ أمني جسيم: تم الكشف عن [Committed AGE Secret Key] أو [Committed admin/admin credentials]`
* **السبب:** تم تضمين مفتاح تشفير حقيقي أو تجريبي غير معتمد، أو تم إيداع ملف بيئة (`.env`) أو بيانات اعتماد صريحة ومحمية في الكود المصدري.
* **كيفية المعالجة الآمنة:**
  1. قم بإزالة الملف أو المفتاح السري المسرب فوراً من الملف المستهدف.
  2. إذا تم الدفع بالتعديل للمستودع، يجب عليك إعادة كتابة تاريخ Git لتصفير التزامات الملفات وتجنب بقائها في التاريخ التاريخي باستخدام `git filter-repo` أو `git filter-branch`.
  3. لا تقم أبداً بمحاولة التفاف الفحص أو تعطيله.

---

## 2. الفشل في التدقيق المعماري (Architectural Governance Failures)

* **الأعراض:** فشل مرحلة `architecture` مع ظهور رسائل خرق الحدود الطبقية المعرفة.
* **السبب:** كتابة استعلامات SQL مباشرة خارج مجلد المستودعات `src-tauri/src/repositories/` أو تضمين تبعيات برمجية محظورة هيكلياً أو إجراء عمليات تخزين غير مصرح بها.
* **كيفية المعالجة الآمنة:**
  1. قم بتشغيل الفحص المعماري محلياً لتشخيص الخلل بدقة:
     `bun run check:arch`
  2. انقل كافة منطق الوصول لقاعدة البيانات والـ SQL إلى طبقة المستودعات (Repositories) واستدعها عبر الخدمات (Services).
  3. التزم بالحدود والقواعد البرمجية الصارمة ولا تحاول التفاف أداة الفحص المعماري.

---

## 3. الفشل في حوكمة الوثائق وسجل التغييرات (Documentation Failures)

* **الأعراض:** فشل مرحلة `documentation` أو `release_integrity` مع رسائل خرق حوكمة الوثائق.
* **السبب:**
  * فقدان أحد المستندات التقنية الستة الإلزامية.
  * تضمين أحد العبارات الترويجية غير الواقعية المحظورة مثل (`tamper-proof` أو `perfectly secure` أو `military-grade`).
  * عدم اتساق رقم الإصدار في `package.json` مع `Cargo.toml` أو غياب توثيق الإصدار الحالي في `CHANGELOG.md`.
* **كيفية المعالجة الآمنة:**
  1. قم بتشغيل أدوات الفحص محلياً للتعرف على الخطأ:
     `bun run scripts/check_docs_governance.ts`
     `bun run scripts/check_release_integrity.ts`
  2. قم بصياغة الفقرات الوثائقية بلغة هندسية واقعية واستبدل الكلمات المحظورة بالبدائل المقترحة في دليل [DOCUMENTATION_GOVERNANCE.md](file:///docs/technical/DOCUMENTATION_GOVERNANCE.md).
  3. تأكد من مطابقة أرقام الإصدارات بشكل متطابق تماماً في ملفات التكوين.

---

## 4. الفشل في فحوصات الواجهة الأمامية والخلفية (Frontend & Backend Failures)

* **الأعراض:** فشل مرحلة `frontend` أو `backend` بسبب أخطاء Clippy أو التحقق من الأنواع أو الاختبارات.
* **السبب:** وجود تحذيرات Clippy غير معالجة، أخطاء في توافق الأنواع في Svelte 5، أو فشل أحد اختبارات Rust/Vitest الوحدوية والتكاملية.
* **كيفية المعالجة الآمنة:**
  1. قم بتشغيل أوامر التحقق والتنسيق الموحدة محلياً:
     `bun run check`
     `cd src-tauri && cargo fmt --check && cargo clippy -- -D warnings && cargo test`
  2. قم بإصلاح التحذيرات بدلاً من إخفائها عبر وسوم التعطيل.
  3. تأكد من معالجة الأكواد البرمجية غير المستخدمة (Unused Code) والتي يرفضها Clippy تلقائياً في بيئة الإنتاج.
